# 话题发现退役：维护者说明

适用于 v1.0.0。日常用户在主控入口用 `/topic list` 找话题，无需操作本文件。

## 作用与边界

管理员核实某群已解散，并保存删除成功或群状态证据后，可登记退役。列表和本地阅读索引不再显示该群链接；旧创建请求的 `/topic resume` 不自动重建群。原注册表、绑定、消息账本、审批与历史文件保留。

这是发现入口隐藏，不是停止运行任务、取消审批、停用绑定或删除 Codex 对话。若要删除原生对话，仍需单独核对全局绑定和部署。群搜索返回空或临时网络失败，不足以作为群已解散的证据。

## 登记格式

若注册表为 `D:\QIUBridge\state\topics-registry.json`，退役文件为同路径追加 `.retired.json`，即 `topics-registry.json.retired.json`。以下全部为占位示例：

```json
{
  "version": 1,
  "topics": [
    {
      "requestId": "om_ORIGINAL_CREATION_MESSAGE",
      "chatId": "oc_VERIFIED_DISSOLVED_GROUP",
      "threadId": "ORIGINAL_NATIVE_THREAD_ID",
      "retiredAt": "2026-11-05T00:00:00.000Z",
      "reason": "用户要求解散的开发测试群，删除结果已核实",
      "evidenceFile": "D:\\QIUBridge\\evidence\\group-dissolved.json"
    }
  ]
}
```

维护者应核对真实记录与证据、备份现有退役文件后一次性写入完整 UTF-8 JSON，并通过原子替换发布。保留已有条目，避免并发写入。不要修改原创建阶段或删原注册表行。

校验要求：版本为 1，`topics` 为数组；每条精确匹配原 `active` 记录的 `requestId / chatId / threadId`；请求编号不得重复；时间须可解析；原因为非空文字；证据文件为绝对路径。实现校验字段及绑定身份，群解散证据的真实性仍由维护者核实。

文件缺失表示没有退役记录；格式、重复或绑定不匹配时拒绝生成列表，不把错误当成空记录。新版本运行代码在每次列表查询和索引生成时读取该文件，现有原生绑定不因此移除；未更新代码的旧包不会自动识别。

## 验证与恢复

1. 在主控单聊和入口群验证 `/topic list` 不再含旧入口，业务话题仍保留。
2. 核对本地索引只隐藏相应入口，历史文件和原账本仍存在。
3. 验证旧创建请求只报告已退役，不创建替代资源。
4. 有误时保留错误文件和证据，核实后原子恢复正确登记；不要清空账本或重放历史输入。恢复显示前还须确认群实际可用。

源码测试覆盖绑定误配、重复、动态读取、重启后读取、两个控制入口、业务话题保留和旧请求防重建。公开示例不包含个人资源标识。
