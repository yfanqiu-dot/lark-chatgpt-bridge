# QIU Bridge v0.9.3

修复多个工具和控制台子进程集中退出时，完整共享进程扫描逐个补查元数据导致证明超时的问题。

- 每轮只读扫描将缺失信息的原始 CIM 记录按 PID 批量补查，每批最多 128 项。结果仅用于本轮扫描，结束后清除，不作为跨轮缓存或进程操作的身份凭据。
- 原始创建时间、父进程、名称以及已知路径和命令仍逐项比对。重复、复用、变化或不可读的活进程仍拒绝；查询错误和访问拒绝继续保留。补查为空时，仍须由创建时间一致且已退出的原生句柄提供证明。
- 原有完整拓扑、端点归属、五秒证明时效、重试次数、启动空闲及健康失败后提交前阻断要求不变。
- 包含 v0.9.2 和 v0.9.1 的子进程退出证明、话题初始化及接续修复。既有群、对话和账本继续保留，历史输入不会因升级自动重放。

实际扫描压力、现场收发和持续观察分别核验。通过短时压力测试不等于完成全部功能或长期运行验收。
