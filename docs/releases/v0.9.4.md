# QIU Bridge v0.9.4

修复原生对话中断后队列自动调度暂停，飞书新消息虽已接收却一直等待的问题。

- 对话持续空闲时，只接续已被原生队列接收的本群队首请求，使用原 `queuedSubmissionId`，不再次调用 `thread/queue/add`。
- 比对原项目、对话、账本保存的队列编号、客户端消息和原文；分页检查唯一归属及队列顺序。更早的桌面请求、身份或原文变化、重复客户端编号均不会被越过。
- 接续前重新核对工具连接、飞书连接和受管健康状态。遇到桌面并发任务，由原生 `thread/queue/start` 的忙碌拒绝保留原队列，不改用直接输入、打断或追加指令。
- 接续后的首条用户消息仍必须匹配原客户端编号和原文。响应丢失时按原历史核对；同进程内未确认的启动不会再次尝试。恢复已知请求时沿用持久化的原队列编号。
- 包含 v0.9.1～v0.9.3 的话题初始化、全部子进程退出证明、批量元数据补查和健康失败后提交前阻断。

原生行为依据本机固定二进制生成的协议，以及[上游队列回归测试](https://github.com/openai/codex/blob/main/codex-rs/app-server/tests/suite/v2/thread_queue.rs)。升级仍须核对本机版本；现场控制、审批和正常退出重入等验收独立完成后，才标记为全面可用。
