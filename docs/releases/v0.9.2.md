# QIU Bridge v0.9.2

修复完整共享进程扫描遗漏控制台等子进程的退出证明，以及健康失败到渠道停止之间仍可能提交新输入的问题。

- CIM 查询前及查询期间，对所有可访问进程保留只读原生句柄。完整拓扑中的 `conhost.exe` 和其他工具子进程也可按创建时间与退出信号核验；不再仅保留几个固定程序名。
- 只有创建时间一致且原生句柄确认退出，才记录退出证明。不可读活进程、PID 复用和访问拒绝仍拒绝检查，不通过忽略未知进程或增加重试次数来维持运行。
- 受管运行一旦写入健康失败记录，新排队输入和新话题初始化在提交模型前立即拒绝。普通退出的观察阶段仍可完成，但不再继续接受新模型输入。
- 包含 v0.9.1 的话题初始化与接续修复；已建立的群、原生对话和历史结果继续沿用，中断或不明确的旧请求不会重放。

实际完整扫描的验证与基础进程扫描分开记录。短时压力测试不能替代现场收发及持续运行观察；全部原有空闲、身份、工具目录和五秒证明时效门槛保持不变。
