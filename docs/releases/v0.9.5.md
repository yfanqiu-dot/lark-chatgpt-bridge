# QIU Bridge v0.9.5

修复登录入口可能因继承不兼容的 PowerShell 模块路径而无法加载校验命令，以及上次健康故障已完整恢复后仍永久阻止下一次启动的问题。

- 登录入口只在自身进程内使用 Windows PowerShell 自带模块，不修改账户或系统的环境变量，不放宽执行策略或文件校验。
- 仅针对有一致终态、普通桌面恢复证明且无清理错误的 `runtime_health_failed`，允许下一次登录或显式启动进入新的准入检查。仍需确认当前没有旧渠道进程、旧计划任务保持退役，且退役定义未变化。
- 持有上次监督记录的写锁直到新运行指针发布，保留原始错误、结果及账本；新运行保存旧计划、旧记录摘要和本次核对证据。缺失结果、活动运行、回滚失败和未确认创建继续阻断，不自动重试创建。
- 后续冷启动沿用完整原生退出、工具与任务空闲、账本及审批检查。不重放旧输入或未确认回执；有待核对工作的群继续暂停。
- 每次启动记录固定阶段、固定错误代码和 SHA-256 摘要；失败时提示日志位置。不会把原始异常、配置、密钥或对话写入启动诊断。`requested` 与真正的渠道 `running` 明确区分。

包含此前的队列接续、话题初始化、进程退出和短暂断线修复。Windows 登录自动启动已配置不代表当次运行成功，应结合启动诊断、监督状态和监听就绪核对。正常退出 Codex 后渠道继续保持关闭；不承诺断电后任意状态或所有故障的无条件自动恢复。
