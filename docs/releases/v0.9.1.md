# QIU Bridge v0.9.1

修复新话题初始化偶发误报中断，以及已知对话初始化完成后仍无法从原请求接续的问题。

- 原生分页历史可能在轮次尚未结束时暂时显示 `interrupted`。初始化只在存在持久化 `completedAt` 时将失败、中断或取消视为最终结果；不会仅凭临时状态提前结束。
- `/topic resume <原消息编号>` 对已保存原生对话 ID 的初始化请求，先核验项目、目录和持久完成轮次，再接续原请求。不会再次调用 `thread/start` 或重放初始化输入。
- 无对话 ID 的不明确创建、未知建群结果及没有持久完成证明的对话仍保持暂停。原群、原对话和账本不清空。
- 只读 Windows 进程扫描在 CIM 查询前及查询期间保留候选进程句柄，避免测试等短生命周期子进程在 CIM 返回前退出导致失去核对机会。只有创建时间一致且原生句柄已发出退出信号时才记录退出；PID 复用、身份不明的活进程和访问拒绝仍阻止检查，不增加重试次数或放宽空闲门槛。

包含 v0.9.0 的登记群完整模式及全部修复。范围和安装方式见[日常使用与运维](../desktop-p4-deployment.md)与[安装指南](../../README.desktop.md)。现场核验独立记录，不以单元测试替代真实收发。
