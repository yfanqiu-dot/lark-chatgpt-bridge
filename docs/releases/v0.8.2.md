# QIU Bridge v0.8.2

修复新版 Codex 已加载临时内部对话时，启动检查把其“不支持任务队列”的原生拒绝当作接口不支持而停止的问题。

- 只接受未绑定、原生状态为空闲、无活动标记的临时对话，其队列第一页返回匹配本对话 ID 的精确 `-32600` 拒绝。两次扫描、已加载集合、完整工具目录、身份和五秒证明时效继续核对。
- 绑定对话不得为临时对话。持久对话仍需完整读取所有队列分页，存在排队输入、后续分页失败、未知错误、审批或活动任务均拒绝启动。
- 区分请求被拒绝与未知方法，保存失败方法、对话 ID、轮次、临时类型和错误摘要，避免只凭错误代码推断原因；不保存原始错误、消息或凭据。
- 修正自动打开后的操作顺序。窗口打开后先保持空闲，实际启动检查完成后再使用；不能立即向安装助手发消息。
- 配置集成测试的假时钟自动前进，避免真实 Windows 文件重试停在被冻结的计时器上；降低心跳测试的读写频率，保留所有状态和身份断言。运行程序的文件保存逻辑未因此改变。

在隔离空目录用当前随附 CLI 真实复现了持久与临时队列的不同响应，没有提交模型输入。旧运行只保留方法和错误代码，无法据此证明每次拒绝都来自相同原因；本版同时补足诊断。新部署仍须现场验证，不能沿用 v0.8.0 的现场结论。

Windows x64、Node.js 22 LTS。单群支持范围、安装方式和历史账本保护不变，详见[运维说明](../desktop-p4-deployment.md)和[兼容性说明](../compatibility.md)。
