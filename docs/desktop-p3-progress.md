## 本轮变更

- 重启恢复：有明确 `turnId` 的未完成账本记录自动核对一次，沿用原轮次；无编号或核对失败保持 `uncertain`，暂停本群新任务，不猜测、不重发。仍可显式 `/reconcile` 再核对。
- 并发控制：入口群建话题保持串行；已绑定群独立处理，不被其他话题的慢速创建阻塞。桌面工具验证完成后再次核对任务空闲状态，减少校验期间桌面开始新任务造成的竞争。恢复订阅活动任务时，bridge 与 host 不主动覆盖该任务的工具配置。
- 审批恢复：卡片发送尝试及回执持久化；重启关闭旧卡片，网络失败保留关闭意图并重试同一卡片。发送回执不明不重发。旧连接事件不能处理新连接的审批，审批决定不自动重放。飞书通知失败不触发桌面任务重新连接或重复提交。
- 运行状态：`/status` 增加本群结果回传待核对、审批卡片待关闭和回执不明数量。结果先保存再发送，回执丢失保留 `/result` 取回路径。
- 退出清理：停止接收新群请求，等待已接收请求和项目记录写入完成后释放运行锁，避免下一进程与旧写入并行。账本增加字段类型检查，损坏记录不进入恢复流程。
- CI：沿用三个操作系统的测试矩阵，将 Node 20 更新为 Node 22，与桌面桥接所需的原生 WebSocket 运行时一致。修复后的代码提交 `85c36ec` 在 [GitHub CI](https://github.com/yfanqiu-dot/lark-chatgpt-bridge/actions/runs/36298068948) 的 Windows、Linux、macOS 作业均通过。
- 跨平台测试：首轮 macOS CI 暴露临时目录别名与真实路径不一致，已将模拟任务的项目路径按 `realpath` 规范化，与实际身份校验的输入约定一致；保留生产代码的严格路径校验。子进程测试在准备失败时直接报告退出原因，避免等到超时。

现场采用既有 A/B/C 群和任务，所有用户身份消息、卡片点击由本人完成。每项记录消息、轮次、回执、项目记录和恢复状态到本机忽略目录，文档仅保留脱敏结论。故障注入只针对受控实例，不修改正式旧 bridge。窗口结束先保存报告，再按协调程序恢复普通桌面及唯一旧 bridge。

## 明确保留的边界

- 客户端的空闲检查与 `turn/start` 之间不是原子操作；尚未声称彻底消除两端同时提交的最后一段竞争，必须通过真实服务端现场用例关闭。
- 无卡片回执无法定位并自动关闭远端卡片；旧 token 拒绝是执行保护，不能伪称该卡片画面已关闭。
- 无 `turnId` 的未知提交不自动匹配相似提示词。此类情况需要原生历史人工核实，不自动重放。
- `/stop` 只请求结束已知轮次，已启动的外部命令不保证被终止。
- 独立 `decline`、富文本 `post` 等未取得现场证据的历史边界不因本次回归而自动变为通过。
- P3 必须完成现场故障清单和约定时长的运行观察，才能关闭；正式部署、常驻服务切换、旧 bridge 清理属于 P4。
