# 办公场景与使用指南

适用于已经完成配置、消息渠道就绪的 QIU Bridge v0.9.4。先从一个群验证收发，再根据需要启用多话题。

[返回中文介绍](../README.zh.md) · [English examples](office-workflows.en.md) · [安装配置](../README.desktop.md) · [运维说明](desktop-p4-deployment.md)

## 它怎样帮你提高办公效率

Bridge 把飞书里的文字请求送到你自己的 Codex 桌面对话，再把最终文字结果带回群里。你可以利用手机处理零散时间里的工作，同时保留电脑上的项目材料和上下文。

| 平时遇到的情况 | 可以怎样使用 |
|---|---|
| 人已离开电脑，临时想起一项工作 | 从飞书发起请求，让开着的电脑继续处理 |
| 同一份材料需要反复修改 | 在原群补充要求，回到桌面后继续同一条对话 |
| 同时跟进周报、客户方案等不同事项 | 为事项创建独立话题群，各自接续对应的项目对话 |
| 做到一半需要换重点 | 用 `/steer` 补充当前任务要求，或用 `/stop` 请求停止 |
| 没看到结果，不确定是否已经做完 | 先查 `/status`，再用 `/result` 取回已保存的结果 |

适合已经在 Windows 上使用 Codex，希望通过飞书继续自己项目工作的个人用户。目前每套安装由配置的所有者控制，其他群成员不会自动获得操作权限。

## 五个可以照着试的办公场景

下面是**提问示例**。请替换成自己的材料和目标；能否读取文件、运行命令或访问业务系统，取决于 Codex 已配置的工具和权限。群消息中的文件路径必须是运行 Bridge 的电脑能够访问的路径，不能指向手机里的文件。

### 1. 下班路上，先整理周报草稿

前提：项目目录里已有本周的工作记录，Codex 能读取这些文件。在对应群里发送：

```text
@机器人 根据项目目录里本周的工作记录，整理一份周报草稿。
按“完成事项、未完成事项、风险、下周计划”四部分组织；
标注依据的文件，缺少的信息列为待补充，不要推测，也不要对外发送。
```

收到草稿后，可以继续发“压缩到 500 字，先写需要负责人协调的事项”。手机上先确定内容结构，回到电脑再核对原材料、完成定稿，减少来回切换和重复交代背景。

### 2. 会后，把讨论文字变成行动清单

将你已经取得的会议记录文字粘贴到群消息中：

```text
@机器人 请整理下面的会议记录，输出：已确定的结论、待办、待确认问题。
待办按“事项、负责人、截止时间”列成表；没有明确的人名或时间写“待确认”。
这一步只整理，不创建任务、不发送通知。

会议记录：
【在这里粘贴会议文字】
```

你会在飞书收到便于核对的文字清单，之后可以继续补充负责人或调整措辞。自动录会、获取逐字稿和创建飞书任务，需要另行配置相应工具并授权。

### 3. 见客户之前，快速梳理背景和问题

前提：客户背景和方案资料已放在对应项目内。

```text
@机器人 根据项目里已有的客户背景和方案资料，做一份十分钟会前速读。
分成：客户已确认的需求、当前方案、还缺的信息、建议会上确认的五个问题。
注明来源文件；资料中的事实和你的建议请分开写。
```

在路上先看重点；会后在原群补充新信息，再让 Codex 更新方案草稿。不同客户或事项可以使用独立话题，便于持续跟进。

### 4. 用已有数据，先拿到一份业务小结

前提：电脑项目内已有 CSV 等数据文件，Codex 配有可用的数据读取或分析工具。

```text
@机器人 请先确认能否读取项目里的 sales.csv。
如果可以，按地区汇总销售额，列出前三名，并检查是否有空值或重复记录。
说明统计口径和无法确认的地方，最后给出一段可以放进周报的文字。
不要修改原始文件；如果无法读取，请说明原因。
```

在飞书先查看数字、口径和结论，再决定是否继续深入分析。当前 Bridge 主要回传文字结果；生成在电脑上的表格、图表等文件，需要到电脑查看，或通过另行配置的文件工具交付。

### 5. 分事项跟进，让不同工作各有上下文

启用完整模式后，可以在**入口群**创建话题。例如：

```text
@机器人 /topic new main 周报整理
```

这里的 `main` 是已配置的项目标识，新装向导默认使用这个名称；请按自己的配置替换。Bridge 会为该事项创建一条真实 Codex 项目对话和一个对应的飞书私有群。

之后在新群 @ 机器人处理周报，在另一个话题群跟进客户方案。每个群对应自己的对话；不同项目也可以分别配置。**这里的“话题”是独立对话及其群，不是飞书群内的一条消息串。** 首次安装默认只验证单群，新话题功能需按[完整功能部署](desktop-p4-deployment.md#完整功能部署-v090)启用。

## 如果想进一步结合飞书文档、日历和任务

**读取飞书云文档、查询日历、创建任务或更新多维表格，需要 Codex 另行安装相应连接器、技能或 CLI，并完成所需授权。** 把一个文档链接发到群里，并不自动赋予读取权限。

配置完成后，可以在原对话里继续提出这样的请求：

- “读取我有权限访问的这篇飞书文档【链接】，整理三个重点和待确认问题，保留原文。”
- “把刚才会议记录中的待办整理成拟创建的飞书任务清单，先让我核对负责人和时间。”
- “查询我明天的日程，按会议列出需要准备的材料；没有依据的内容标为待确认。”

先让助手列出拟执行内容、核对目标，再按需要授权写入。Bridge 提供从飞书发起和接续工作的入口；实际业务能力与数据访问范围由你配置的工具及权限决定。

## 日常使用：发起、补充、核对、接续

1. **先让电脑上的 Bridge 就绪。** 电脑保持开机、联网，Codex 已登录；启动检查完成后再发任务。
2. **在绑定群里 @ 机器人发文字。** 说明使用哪份材料、想得到什么、有哪些限制。通常最终文字结果会回复到这条请求。
3. **根据结果继续追问。** 后续请求沿用本群绑定的原对话。任务仍在执行时，可用 `/steer` 补充要求。
4. **需要审批时核对卡片。** 查看具体命令或文件变更，再决定；部分特殊权限和补充信息仍需回桌面处理。
5. **回到电脑继续。** 打开对应项目对话，核对材料和产物，完成最后的编辑与交付。桌面中的全部过程不会自动镜像到飞书。

| 你想做什么 | 在群里 @ 机器人发送 | 使用时注意 |
|---|---|---|
| 看当前状态 | `/status` | 查看运行、排队和待核对情况 |
| 补充正在执行的任务 | `/steer 把需要我决策的事项放在最前面` | 需要当前有可接续的活动轮次 |
| 停止当前任务 | `/stop` | 请求停止本群发起的轮次；已启动的外部命令可能继续运行 |
| 再取一次最近的结果 | `/result` | 读取已保存的结果，不重新执行任务；也可用 `/result <消息编号>` 指定请求 |
| 核对不确定的任务 | `/reconcile` | 按原请求核对，不能把它当作重新执行按钮 |
| 新建事项 | `/topic new main 客户方案` | 仅在已启用创建功能的入口群使用 |

遇到延迟或未回复，先查状态、取回结果；不要连续重复发送同一项工作。电脑睡眠、断网、Codex 更新或权限异常都可能影响执行。进一步排查见[运维说明](desktop-p4-deployment.md)。

Bridge 安装在**自己的 Windows 电脑**上，使用自己登录的 Codex 和自己配置的飞书机器人。电脑需要保持开机联网。它是社区开发的第三方集成，并非 OpenAI 或飞书官方产品。
