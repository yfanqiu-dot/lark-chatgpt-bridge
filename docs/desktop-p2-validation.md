## 首轮结论

**P2 尚未通过现场验收。** 受控程序确认普通桌面及唯一旧 bridge 已暂停，共享桌面工具和 P2 入口群监听均就绪。用户本人发送第一条建话题命令后，机器人收到事件并创建了 FEISHU 项目的原生任务 ID，但任务身份复核失败，未创建新飞书群；机器人把失败及同一请求的接续入口回复到原群。注册表停在 `thread_ready`，没有重发创建调用。

定位：`thread/start` 返回 ID 后立即关闭该连接，空任务未形成可恢复的 rollout。后续 `thread/read` 无法得到正确项目身份，`thread/resume` 返回没有 rollout；同一任务上的独立初始化调用亦找不到任务。受控探针证实，在创建连接里先命名可以让新连接读到项目，但仍没有桌面可恢复的对话历史；同连接完成首个无工具初始化轮次后，项目身份及历史可由新连接和桌面工具读取。探针留下的一条可见任务已归档。原始诊断见 `.p2-local/created-thread-inspection.json`、`created-thread-resume.json`、`created-thread-bootstrap.json`、`name-persistence-probe.json`、`start-persistence-probe.json` 和原群机器人回执。

修复：新建任务返回 ID 时，先以 `thread_initializing` 将 ID 写入注册表，再在**同一连接**命名并提交仅作初始化的首轮指令，等待该轮结束后才复核项目及持久化轮次，再建群。首轮内容不会写入项目 Markdown 对话记录。初始化结果不明会停在 `thread_initializing`，人工核实持久化历史后才能续办；不会盲目重复 `thread/start`。专项回归新增了“先记账、同连接命名及初始化、跨连接身份复核”和初始化结果不明时不建群测试。

修复后的源码验证：桌面专项 54 项通过，全仓单元测试 474 项通过，TypeScript 类型检查、Vite/tsup 构建通过。**修复后的新任务、真实飞书建群与双向接续尚未在新监听进程上实测**；不能用这些离线结果替代 P2 通过。
