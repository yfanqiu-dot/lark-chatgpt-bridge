# 桌面版设计与验收摘要

本文保留维护者需要的设计约束和验收边界。当前安装见[安装指南](../README.desktop.md)，日常使用见[办公指南](office-workflows.zh.md)和[运维说明](desktop-p4-deployment.md)。

## 核心设计

- 一个已登记飞书群对应指定项目中的一条真实 Codex 对话。登记所有者控制执行和审批；群成员身份不自动获得权限。
- 桌面与 Bridge 共用受管 App Server。新群请求进入原生持久队列，以原消息标识核对归属；未知提交结果不会通过再次添加输入来恢复。
- 桌面已有活动轮次时，群输入等待。群任务活动期间，桌面追加可能被原生后端并入该轮次；遇到未确认混合输入时保留待核对状态，不回传为群成功结果。
- 本地账本保留请求、原生轮次、结果和回执。回执不明时停止自动发送，通过显式结果取回和核对处理。
- 支持的审批必须匹配群、所有者和活动原生请求。特殊权限、补充信息及不完整变更详情交回桌面处理。
- 新话题先保存创建进度和绑定，再激活；创建结果不明时核实原资源后接续，保留原群和历史。

## 发布与运行约束

Windows 桌面版通过 GitHub Release 分发，原独立 CLI 后端及其[说明](cli-backend.zh.md)继续保留。两个入口的运行方式和能力边界不同。

受管部署校验 Codex 二进制、工具目录、项目与对话归属、原生进程身份、锁和连接。正常退出桌面时关闭渠道；故障保存证据并尝试恢复普通桌面。安全与完整性检查不因排障放宽。

原始群记录、运行账本、审批回执、进程证明和个人故障时间线属于本机资料，不随源码和安装包分发。早期阶段开发流水已从当前文档树移出，维护者私下保留归档；本摘要不宣称移除了已有 Git 历史。

## 已有验收与边界

- 基础闭环：群文字收发、原项目及对话接续、状态、追加、停止、支持的审批和保存结果取回。
- 多话题：显式创建与接续、同项目及跨项目路由、绑定恢复、所有者与群范围检查。
- 恢复：原生队列与已知轮次核对、回执不明不重发、限定故障注入和普通桌面恢复。具体通过项不推广为所有并发、崩溃或网络情形均通过。
- v0.9.4：中断后的自动队列接续、群内控制及审批后命令执行；本机启动、正常关闭后重新接入及十五分钟有限健康观察通过。版本修复见[发布说明](releases/v0.9.4.md)。

上述为维护机器上的限定验证。其他机器、Codex 更新及新增项目都需要重新核对；不构成长期无人值守可靠性承诺。本机普通 Windows 沙盒初始化错误尚未修复，审批后执行路径已验证，详见[使用边界](../README.zh.md#版本与边界)。

## 开发检查

使用锁定依赖运行 `pnpm test`、`pnpm typecheck`、`pnpm build` 和 `node tools/check-doc-links.mjs`。自动测试和构建包含 Windows、Linux、macOS；桌面运行支持仍为 Windows x64。

公开贡献应采用账户的 GitHub noreply 提交邮箱。示例和测试使用合成标识；不要提交个人运行数据或把原始日志贴入公开 PR，参见[安全说明](../SECURITY.md)。
