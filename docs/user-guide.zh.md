# QIU Bridge 完整使用手册

适用于 **v0.10.0 Windows 桌面版**。Bridge 让你从飞书接续自己电脑上真实的 Codex 项目对话：单聊安排工作，专项群处理具体事项，回到电脑继续审阅和交付。

[首页](../README.zh.md) · [安装配置](../README.desktop.md) · [办公案例](office-workflows.zh.md) · [部署与恢复](desktop-p4-deployment.md) · [English guide](user-guide.en.md)

## 1. 先安装，再开始工作

需要自己的 Windows x64 电脑、Node.js 22 LTS、已登录的兼容 Codex 桌面，以及已发布权限的飞书机器人。首次安装需要命令行配置，按[安装指南](../README.desktop.md)先绑定一个已有项目和对话、验证收发，再启用多话题及可选的[单聊主控](desktop-p4-deployment.md#单聊主控配置-v0100)。单聊不会因安装自动开启。

电脑须保持开机、联网、当前 Windows 用户已登录；这是运行在自己电脑上的工具。飞书文档、日历、任务、GitHub 和数据分析等业务能力，需要 Codex 另行配置工具及授权。

安装登录入口后，**登录 Windows 会自动尝试启动，无需每天再点击 `QIU New Bridge`**。启动会核对程序、所有者、项目、队列和桌面空闲状态，可能需要等待。不要同时手动抢先打开普通 Codex 或反复点击启动入口。若普通 Codex 已打开，先保存工作并正常退出，让入口继续；等待有十分钟上限。正常退出受管 Codex 会同时关闭渠道；需要继续工作时再用同一入口启动。

首次安装、重启后或升级后，可先发 `/status`，再发一条新的简单文字请求确认收发。仅看到窗口打开不代表渠道已就绪。运行状态检查方法见[安装第六步](../README.desktop.md#6-首次启动与验收)。生产运行不依赖限时测试窗口；有界观察通过也不等于已证明数天无人值守可靠性。

## 2. 选对入口

| 入口 | 发送方式 | 用途 |
|---|---|---|
| 已配置的机器人单聊 | 直接发文字，无需 @ | 主控入口、独立工作对话、创建或查找话题 |
| 已配置的入口群 | 每条消息 @机器人 | 保留群入口，创建或查找话题，也可继续本群工作 |
| 已登记的话题群 | 每条消息 @机器人，包括命令 | 针对本事项持续工作，查看和控制本群任务 |

仅配置的所有者可操作；把其他人拉进群不等于授予其控制电脑的权限。陌生群和未绑定单聊不会接入。

每个入口都有自己的 Codex 对话和消息账本。**单聊不是全局任务控制台**：单聊的 `/stop` 不会停止 B 群，单聊的 `/result` 也不会读取 A 群。要控制哪个事项，就进入对应群。普通文字里提到群名不会切换路由，也不会自动建群。

话题指“一条 Codex 对话 + 一个飞书私有普通群 + 本地绑定”。它不是飞书群内的一条回复串，也不是飞书原生话题群功能。同一项目下不同话题可以访问同一批项目文件；对话分开不意味着文件相互隔离。

## 3. 十分钟上手：从单聊发起一份周报

1. 在已配置的机器人单聊发送 `/help`，查看可用项目标识。以下 `main` 仅为示例，换成实际标识。
2. 发送一次：

   ```text
   /topic new main 周报-2026-W42
   ```

3. 等创建回复，点击“进入话题群”，在群里 **@机器人** 发送：

   ```text
   根据本项目本周的工作记录，起草一份周报。
   分为完成事项、未完成事项、风险、下周计划；注明来源文件。
   缺少的信息标为待补充，不猜负责人或日期。
   先返回文字草稿，不向外发送，不修改原始记录。
   ```

4. 需要调整时，在同一群继续 @机器人追问。任务还在执行时，可以发 `/steer 最终控制在500字内，把需要我决策的事项放在最前面`；若当前已结束，直接发送新的修改要求。
5. 想了解进度就发 `/status`；收到结果后可用 `/result` 再取一次已保存答案。
6. 回到单聊发送 `/topic list`，以后从列表进入同一群继续。回到电脑可在对应项目对话审阅材料和产物。

不要因创建较慢重复发 `/topic new`。**相同标题不去重**：不同新消息即使标题相同，也可能创建第二个话题。同一事项优先继续原群。

## 4. 命令速查

表中命令均为小写。群内每条都须 @机器人；已启用的单聊无需 @。尖括号表示需要替换的值，方括号表示可选参数，实际发送时不带括号。

| 命令 | 在哪里用 | 准确含义与注意事项 |
|---|---|---|
| `/help` | 单聊主控、入口群 | 查看入口用法和已配置项目标识 |
| `/topic list` | 单聊主控、入口群 | 查看已登记话题与群入口；不是运行中任务总览 |
| `/topic new <projectKey> <title>` | 已启用创建的单聊主控、入口群 | 在指定项目新建真实对话及私有群；标题为 1–60 个可见字符 |
| `/topic resume <messageId>` | 单聊主控、入口群 | 接续已保存、未完成的原创建请求；使用原创建消息 ID。不是恢复已删除群或对话 |
| `/status` | 本对话 | 查看活动、排队、不确定记录、回执及审批情况 |
| `/steer <text>` | 本对话 | 为当前可接续的活动轮次补充要求；不是给下一个排队任务留言 |
| `/stop` | 本对话 | 请求停止本渠道发起的当前活动任务；不会停止其他群或桌面独立任务，**不会清空排队请求**，后续请求仍可能开始。已启动的外部命令可能继续运行 |
| `/result` | 本对话 | 返回最近一条**已保存结果的非命令请求**；最新请求尚未完成时，可能返回更早答案 |
| `/result <messageId>` | 本对话 | 按原始输入消息 ID 取回已保存结果。不是群 ID、对话 ID 或轮次 ID；不会重新调用模型 |
| `/reconcile` | 本对话 | 无参数，核对最早一条不确定记录；繁忙时拒绝执行。缺少原生标识时须到桌面人工核对，不会自动重提任务 |
| `/approve <token> accept` | 收到审批的本对话 | 提交同意决定；须使用通知里的有效 token |
| `/approve <token> decline` | 同上 | 拒绝该审批 |
| `/approve <token> cancel` | 同上 | 提交取消决定。决定已提交不等于命令执行已成功 |

审批优先使用收到的卡片，核对具体命令、路径或变更后决定。token 不能跨群、跨所有者使用；部分特殊权限及补充信息需回桌面处理。不要将审批 token 或原始账本贴到公开问题中。

## 5. 等待、并行和中断的小技巧

- **先查状态，再决定下一步。** “未回复”可能是桌面忙、排队、执行中、等待审批、回执不明或渠道离线。不要把延迟直接当作丢失。
- **避免重复提交。** 去重依据原始消息 ID，不依据文字内容。把相同要求再发一条，是新任务，可能重复生成文件或执行操作。
- **一群一事项，持续追问。** 对短期工作用“客户方案-第一版”等易辨名称；同一项目多个群避免同时修改同一文件，可明确输出到不同文件名。
- **想补要求用 `/steer`，想改已完成结果就正常追问。** 尚未开始的任务没有可追加的活动轮次；先看 `/status`。
- **停止后再看队列。** `/stop` 只针对当前活动请求；如果你已连续发多条，后面的仍可能执行。本版没有清空队列命令；需停止全部后续工作时，在桌面核对并由维护者处理，别继续加新请求。
- **保留原请求和最后一条状态。** 结果不明时在原群用 `/result` 或 `/reconcile`；不要新建空账本、重复创建资源来“恢复”。

## 6. 更有效地安排办公任务

一个好请求通常说清四件事：**材料在哪、希望得到什么、判断标准、允许做哪些操作**。例如：

```text
读取本项目的 sales.csv，先说明统计口径和空值、重复记录情况。
按地区汇总销售额，返回前三名及一段可放进周报的文字。
保留原文件；如果无法读取或字段有歧义，请说明并等我补充。
```

结合飞书可逐步这样用：

| 工作 | 推荐流程 |
|---|---|
| 会前准备 | 发可访问的客户资料路径或粘贴背景 → 列已知事实、缺失信息、五个待确认问题 |
| 会后推进 | 粘贴会议文字 → 提取决策、行动项、负责人和日期 → 核对后再授权创建飞书任务 |
| 日报周报 | 同群持续补充进展 → 定期整理草稿 → 回桌面核对来源并交付 |
| 文档协作 | 配置文档读取能力后发链接 → 要求引用来源、区分事实与建议 → 明确目标文档后授权更新 |
| 项目专项 | 单聊建话题 → 群里多轮推进 → 用 `/topic list` 找回入口，避免背景混在一起 |

Bridge 负责消息和对话接续；并不自带上述全部业务工具。文档链接本身不赋予权限。不要让助手在材料不足时猜测会议结论、负责人或日期。更多可复制模板见[办公案例](office-workflows.zh.md)。

**文件与附件：** 当前支持文字输入和最终文字答复，手机上传的图片或附件不会自动作为模型输入。给出的本地路径须存在于运行 Bridge 的电脑上。生成的表格、图片、报告仍在电脑上，不会因生成成功自动上传飞书；可要求返回绝对路径，回电脑打开，或另行配置并授权文件上传工具。桌面全部工具过程也不会完整镜像到飞书。

## 7. 话题改名、归档和删除

本版有创建、列表和创建接续，**尚无统一的改名、归档、停用、解绑或删除命令**。不要发送假想的 `/topic delete`、`/topic rename` 或 `/topic archive` 并期待生效。

| 你在另一侧做的事 | 当前影响 |
|---|---|
| 修改飞书群名 | 群 ID 未变，通常继续路由；Codex 标题及 `/topic list` 保存的标题不会自动同步 |
| 修改 Codex 对话标题 | 对话 ID 未变，通常继续路由；飞书群名及保存的标题不会自动同步 |
| 在 Codex 归档对话 | 不等于停用 Bridge 绑定，不能用作停止入口的开关 |
| 在飞书解散群 | 该消息入口不可用；本地绑定和 Codex 对话仍保留，正在运行的任务不会仅因解散自动取消 |
| 删除已绑定 Codex 对话 | 后续请求可能失败；下一次原绑定/启动核对也可能阻断整个 Bridge，包括其他群和单聊。目前不会自动隔离损坏话题 |
| 用同名群或同名对话重建 | 新 ID 不会自动替代原绑定；`/topic resume` 也不是删除恢复命令 |

飞书“从自己的会话列表移除”与解散群不同；是否还可进入取决于群是否存在及成员权限。仅改显示名不代表删除资源。

当前建议保留已有群和对话，旧事项停止追加工作即可。确需彻底移除时，先核对任务、排队和结果，再由维护者一致处理绑定与部署；不要自行删一行登记表或建空账本绕过检查。项目内若启用了本地对话文本投影，它也只是部分用户文字及最终结果的阅读副本，不是完整备份或话题停用功能。

## 8. 常见问题

| 现象 | 先做什么 |
|---|---|
| 群内没反应 | 检查是否 @、是否登记群、是否配置所有者发出；再核对电脑联网及服务状态 |
| 单聊没反应 | 确认已显式配置该单聊；普通安装默认关闭，不会接入所有私聊 |
| 状态有排队 | 等当前任务完成；桌面自己的活动任务也可能让 Bridge 等待，不要重复发任务 |
| 等审批 | 核对卡片并决定；特殊权限回桌面处理 |
| `/result` 看起来是旧答案 | 最新任务可能尚未保存结果；结合 `/status`，必要时按原输入消息 ID 查询 |
| 有不确定状态或发送回执不明 | 保留记录，原群 `/reconcile` 或 `/result`；不要重放业务操作 |
| 话题创建迟迟无结果 | 不重复 `/topic new`；保留原消息 ID，按提示接续或交维护者核对 |
| 登录后未连上 | 检查唯一 Startup 入口、普通 Codex 是否抢先打开、启动状态及失败提示；不是重复点图标 |
| Codex 升级后无法启动 | 新版本/程序 SHA/工具目录需重新验证并准备部署，不跳过完整性检查 |
| 执行提示 Windows 沙盒初始化错误 | 如实保留错误；已验证的审批执行路径不代表所有沙盒环境均已修复，回桌面核对 |

反馈问题时提供 Bridge/Codex/Windows 版本、时间、入口类型、命令、期望和实际结果，并附脱敏状态。不要公开 App Secret、个人路径、群/用户标识、审批 token、完整聊天或业务账本。日志和恢复步骤见[运维说明](desktop-p4-deployment.md)，支持范围见[兼容性](compatibility.md)。
